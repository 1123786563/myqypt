# U04 Usage View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付用量查看页：按 Product/Meter 展示 Included Allowance 消费进度、超出部分的预付余额扣费（Rated Result，T46/T48）、以及可解释明细（T52），让 Billing Member 能核对「用量 → 金额」链路（基线 §12）。

**Architecture:** 页面 = /app/usage + BFF 聚合端点 GET /portal-api/usage/summary?period=month。BFF 复用 T52 可解释账单与 T45 Allowance 数据源：每个 Meter 返回 { used_quantity, unit, allowance_quantity?, allowance_consumed?, overage_cost_fen, rated_price_version? }。浏览器不直连 ClickHouse/OpenMeter；聚合、取整与金额计算全部在 BFF。进度条用 U00 UsageProgress，金额用 U00 formatCnyFen。按日/月切换只改查询参数，不做前端聚合。

**Tech Stack:** React 19、TypeScript、Vite、Tailwind 4、TanStack Query、Vitest Browser、Playwright、Go BFF

**Spec:** [GitHub Issue #126](https://github.com/1123786563/myqypt/issues)、docs/architecture/architecture-baseline-risk-assessment-v1.1.md §12/§13、ADR-0016、ADR-0020、docs/superpowers/plans/2026-08-24-t45-included-allowance.md、2026-08-24-t52-explainable-bill.md

## Global Constraints

- 用量数据只能来自 BFF（其背后是 Canonical Usage / Rated Result）；浏览器禁止直连 OpenMeter/ClickHouse/Kafka。
- 金额列必须可下钻：点击金额进入 T52 解释视图（Price Version、rounding、Adjustment 引用），禁止只显示不可解释的汇总数。
- Allowance 展示用「已用/总额 + 进度条」；超用部分单列「超额扣费」，不得混入 Allowance 内。
- 时区固定 Asia/Shanghai，period 参数白名单（day/month），BFF 按 occurred_at 聚合；迟到事件（T46）在页面上标注「按历史价格计费」。
- 页面不展示任何 meter 的绝对 Token/字符明细正文，只展示数量与金额。
- 测试用内存 Usage 数据源；不得包含客户 Prompt/文档内容。
